# Dark Mode — CRM تخصصی املاک

این سند رفتار حالت تاریک را تعریف می‌کند. Dark Mode باید در همه صفحات و کامپوننت‌ها پشتیبانی شود، بدون اینکه چیدمان، فاصله‌ها، تایپوگرافی یا دسترسی‌پذیری تغییر کند.

---

## 1. اصول کلی

- Dark Mode باید با تغییر توکن‌های رنگی پیاده‌سازی شود، نه با تغییر ساختار صفحات.
- هیچ صفحه‌ای نباید در Dark Mode شکستگی، کنتراست کم یا متن غیرقابل خواندن داشته باشد.
- از مشکی خالص برای پس‌زمینه استفاده نشود.
- از سفید خالص برای متن اصلی استفاده نشود.
- Dark Mode باید با Tailwind CSS و استراتژی class پیاده‌سازی شود.
- انتخاب کاربر باید در localStorage ذخیره شود.
- حالت سیستمی نیز باید پشتیبانی شود.
- در بارگذاری اولیه نباید Flash نامناسب نمایش داده شود.

---

## 2. حالت‌های تم

| حالت | مقدار ذخیره‌شده | رفتار |
|---|---|---|
| روشن | light | همیشه کلاس dark حذف شود |
| تاریک | dark | همیشه کلاس dark اضافه شود |
| سیستمی | system | بر اساس prefers-color-scheme سیستم تصمیم گرفته شود |

### حالت پیش‌فرض
- اگر کاربر قبلاً انتخابی نداشت، حالت پیش‌فرض system باشد.
- اگر system انتخاب شد، باید به تغییرات سیستم نیز واکنش نشان دهد.

---

## 3. کلید ذخیره‌سازی

| مورد | مقدار |
|---|---|
| کلید localStorage | theme |
| مقادیر مجاز | light، dark، system |
| محل اعمال | document.documentElement |
| کلاس اعمال‌شده | dark |

### رفتار ذخیره‌سازی
- هنگام تغییر تم توسط کاربر، مقدار در localStorage ذخیره شود.
- اگر مقدار نامعتبر بود، به system برگردد.
- نباید تم در Cookie ذخیره شود.
- نباید چند کلید مختلف برای تم استفاده شود.

---

## 4. الگوریتم اعمال تم در بارگذاری اولیه

1. خواندن مقدار theme از localStorage
2. اگر مقدار light بود، کلاس dark حذف شود.
3. اگر مقدار dark بود، کلاس dark اضافه شود.
4. اگر مقدار system بود، prefers-color-scheme بررسی شود.
5. اگر سیستم dark بود، کلاس dark اضافه شود.
6. اگر سیستم light بود، کلاس dark حذف شود.
7. اگر مقدار خالی یا نامعتبر بود، حالت system در نظر گرفته شود.

### جلوگیری از Flash
- اسکریپت تشخیص تم باید قبل از render اصلی اجرا شود.
- باید از inline script در index.html استفاده شود.
- نباید ابتدا تم روشن نمایش داده شود و سپس به تاریک تغییر کند.
- در صورت امکان، background اولیه از CSS variable گرفته شود.

---

## 5. پشتیبانی از حالت سیستمی

- باید از matchMedia استفاده شود.
- اگر حالت انتخابی کاربر system باشد، تغییر prefers-color-scheme باید اعمال شود.
- اگر کاربر حالت light یا dark را انتخاب کرد، تغییرات سیستم نادیده گرفته شود.
- listener باید فقط وقتی فعال باشد که حالت system انتخاب شده است.

### نمونه منطق
- اگر theme = system:
  - اگر prefers-color-scheme: dark، کلاس dark اضافه شود.
  - در غیر این صورت کلاس dark حذف شود.
- اگر theme = light:
  - کلاس dark حذف شود.
- اگر theme = dark:
  - کلاس dark اضافه شود.

## 7. قواعد Tailwind CSS

### تنظیمات
- darkMode باید روی class تنظیم شود.
- رنگ‌ها باید به‌صورت semantic تعریف شوند.
- در صفحات از کلاس‌های dark: برای تغییر رنگ استفاده شود.
- از hardcode کردن رنگ خام در کامپوننت‌ها پرهیز شود.

### الگوی پیشنهادی
- bg-background
- bg-surface
- bg-surface-muted
- border-border
- text-text-primary
- text-text-secondary
- text-text-muted
- bg-primary
- text-primary

### قواعد dark:
- برای هر رنگ سطح، باید معادل dark تعریف شود.
- برای borderها باید رنگ dark جداگانه تعریف شود.
- برای hover و focus نیز باید حالت dark تعریف شود.
- نباید برای Dark Mode فقط متن را سفید کرد؛ باید سطح‌ها نیز تغییر کنند.

## 8. رفتار کامپوننت‌ها در Dark Mode

### Sidebar
- پس‌زمینه باید تیره‌تر از Content یا هم‌سطح Surface باشد.
- آیتم فعال باید با پس‌زمینه ملایم primary مشخص شود.
- متن آیتم‌های غیرفعال باید خاکستری روشن باشد.
- Hover باید تغییر ظریف داشته باشد.

### Topbar
- پس‌زمینه Surface تیره
- Border پایینی #334155
- آیکون‌ها #94a3b8
- Search Box باید placeholder کم‌رنگ داشته باشد.

### Card
- پس‌زمینه Surface
- Border ظریف
- سایه شدید نداشته باشد.
- عنوان متن اصلی و توضیحات متن ثانویه باشد.

### Button
- Primary: #3b82f6 با متن سفید
- Secondary: Surface با Border و متن روشن
- Ghost: بدون Border با متن ثانویه
- Danger: #ef4444 یا معادل مناسب با متن سفید
- Disabled: سطح کم‌رنگ و متن غیرفعال

### Input
- پس‌زمینه Surface
- Border #334155
- Focus با primary
- Error با danger
- Placeholder #64748b
- Disabled با سطح کم‌رنگ

### Table
- Header کمی تیره‌تر از Surface
- Rowها Surface
- Hover کمی روشن‌تر از Surface
- Borderها #334155
- متن Header #94a3b8
- متن Cell #e2e8f0

### Modal / Drawer
- Overlay تیره‌تر
- Surface #1e293b
- Border #334155
- عنوان روشن
- متن بدنه #94a3b8

### Toast / Alert
- Success: پس‌زمینه تیره سبز، متن روشن
- Warning: پس‌زمینه تیره کهربایی، متن روشن
- Danger: پس‌زمینه تیره قرمز، متن روشن
- Info: پس‌زمینه تیره آبی، متن روشن
- نباید Alertها در Dark Mode بیش از حد درخشان باشند.

### Kanban
- Board Background: #0f172a
- Column Background: #1e293b
- Card Background: #273449
- Card Border: #334155
- Stage Color باید در Dark Mode نیز قابل تشخیص باشد.
- Deal Card نباید در تاریکی کم‌رنگ و نامشخص شود.

### Chart
- رنگ خطوط محور کم‌رنگ باشد.
- رنگ سری‌ها روشن‌تر از حالت Light باشد.
- Tooltip از Surface تیره استفاده کند.
- Grid خطوط ظریف داشته باشد.

### Image Gallery
- پس‌زمینه Gallery تیره باشد.
- تصویرها نباید بیش از حد روشن به نظر برسند.
- دکمه‌ها باید کنتراست کافی داشته باشند.
- Overlay روی تصویر باید خوانایی دکمه‌ها را حفظ کند.

### Map
- در Dark Mode می‌توان از Tile تیره استفاده کرد یا نقشه را با سطح تیره محدود کرد.
- Markerها باید قابل تشخیص باشند.
- کنترل‌های نقشه باید هدف لمسی کافی داشته باشند.

## 9. فرم‌ها در Dark Mode

- Labelها باید روشن باشند.
- Inputها باید Surface تیره داشته باشند.
- Borderها باید قابل تشخیص اما ظریف باشند.
- پیام خطا باید با رنگ #f87171 یا معادل danger روشن نمایش داده شود.
- پیام موفقیت باید با #4ade80 یا معادل success روشن نمایش داده شود.
- Placeholder نباید با متن اصلی اشتباه گرفته شود.
- دکمه ذخیره باید در هر دو حالت کنتراست کافی داشته باشد.
- فوکوس باید با رنگ primary واضح باشد.

---

## 10. Dark Mode و دسترسی‌پذیری

- کنتراست متن اصلی باید حداقل AA باشد.
- فوکوس باید در Dark Mode نیز قابل مشاهده باشد.
- رنگ‌های وضعیت نباید تنها وسیله انتقال معنا باشند.
- آیکون‌ها و متن‌ها باید در هر دو حالت خوانا باشند.
- Placeholder نباید اطلاعات مهم را منتقل کند.
- نمودارها باید در Dark Mode نیز برچسب‌های خوانا داشته باشند.
- هدف‌های لمسی نباید در Dark Mode تغییر اندازه دهند.

---

## 11. تغییر تم توسط کاربر

### محل کلید تغییر تم
- در Topbar به‌صورت آیکون
- باید در دسترس و قابل تشخیص باشد.
- باید aria-label مناسب داشته باشد: «تغییر حالت روشن/تاریک»

### رفتار
- کلیک روی کلید باید بین light و dark جابجا شود.
- اگر حالت فعلی system باشد، کلیک اول به حالت مخالف ترجیح سیستم برود یا مستقیماً light/dark شود؛ باید رفتار ثابت باشد.
- پس از تغییر، مقدار در localStorage ذخیره شود.
- تغییر باید بدون reload کامل صفحه اعمال شود.
- transition کوتاه برای تغییر رنگ مجاز است.

### گزینه پیشنهادی برای Settings یا Profile
- در صورت نیاز می‌توان انتخاب حالت را در Settings یا Profile نیز قرار داد:
  - روشن
  - تاریک
  - سیستمی
- این انتخاب باید با Topbar sync باشد.

---

## 12. Transition و Motion

- تغییر تم باید transition کوتاه داشته باشد.
- duration پیشنهادی: 150ms تا 250ms
- easing: ease-out
- نباید transition باعث ایجاد Flash یا پرش شود.
- اگر کاربر prefers-reduced-motion دارد، transition رنگی می‌تواند غیرفعال شود.
- Skeletonها نباید در Dark Mode چشمک شدید داشته باشند.

## 13. حالت‌های خاص

### صفحه Login
- باید در Dark Mode نیز کارت مرکزی خوانا باشد.
- پس‌زمینه صفحه نباید مشکی خالص باشد.
- کارت ورود باید Surface تیره داشته باشد.
- پیام خطا باید قابل تشخیص باشد.

### صفحات خالی
- Empty State باید با آیکون کم‌رنگ و متن ثانویه نمایش داده شود.
- دکمه CTA باید در Dark Mode نیز قابل مشاهده باشد.

### صفحات خطا
- Error State باید با رنگ danger روشن و آیکون قابل تشخیص باشد.
- دکمه Retry باید در Dark Mode واضح باشد.

### No Permission
- آیکون و پیام باید کم‌رنگ اما خوانا باشد.
- دکمه بازگشت باید قابل دسترس باشد.

# داشبورد — CRM تخصصی املاک

این سند طراحی داشبورد را تعریف می‌کند. داشبورد باید خلاصه‌ای سریع، قابل فهم و قابل Drill-down از وضعیت فروش، مشتریان، معاملات، وظایف، املاک و فعالیت‌ها ارائه دهد.

---

## 1. هدف داشبورد

- نمایش KPIهای کلیدی در یک نگاه
- نمایش نمودارهای تحلیلی بر اساس بازه زمانی
- نمایش فعالیت‌های اخیر
- نمایش وظایف امروز و وظایف عقب‌افتاده
- نمایش نوتیفیکیشن‌های مهم
- امکان فیلتر بر اساس Agent و Pipeline
- امکان Drill-down به لیست‌های مرتبط
- پشتیبانی از Skeleton، Empty State و Error State
- پشتیبانی از Dark Mode، RTL و Responsive

---

## 3. KPI Cards

### ساختار هر KPI Card
- عنوان فارسی کوتاه
- مقدار اصلی با فرمت فارسی
- آیکون مرتبط
- تغییر نسبت به دوره قبل در صورت فعال بودن مقایسه
- رنگ تغییر: success برای رشد مناسب، danger برای افت مناسب، neutral برای بدون تغییر
- قابلیت کلیک برای رفتن به لیست مرتبط

### قواعد KPIها
- مقدار باید بزرگ و خوانا باشد.
- عنوان باید کوتاه باشد.
- اعداد باید با Intl فارسی شوند.
- مبالغ باید با جداکننده هزارگان نمایش داده شوند.
- درصد باید با نماد ٪ و فرمت فارسی باشد.
- Skeleton برای KPIها الزامی است.
- در صورت خطا، KPI باید Error State کوچک یا Retry داشته باشد.
- در صورت نداشتن داده، مقدار صفر یا Empty State مناسب نمایش داده شود.

### KPIهای اصلی

| KPI | مقدار | Drill-down |
|---|---|---|
| لیدهای جدید امروز | تعداد | /clients با فیلتر تاریخ ایجاد امروز |
| لیدهای جدید هفته | تعداد | /clients با فیلتر تاریخ ایجاد هفته جاری |
| Dealهای فعال | تعداد | /deals با فیلتر وضعیت فعال |
| ارزش Dealهای فعال | مبلغ | /deals با فیلتر وضعیت فعال |
| بازدیدهای ثبت‌شده | تعداد | /interactions با فیلتر نوع بازدید ملک |
| معاملات برنده ماه جاری | تعداد | /deals با فیلتر وضعیت برنده و تاریخ ماه جاری |
| معاملات بازنده ماه جاری | تعداد | /deals با فیلتر وضعیت بازنده و تاریخ ماه جاری |
| نرخ تبدیل لید به معامله | درصد | /reports با گزارش Funnel |
| وظایف امروز | تعداد | /tasks با فیلتر سررسید امروز |
| وظایف عقب‌افتاده | تعداد | /tasks با فیلتر سررسید گذشته |
| املاک فعال | تعداد | /properties با فیلتر وضعیت فعال |
| املاک فروخته‌شده | تعداد | /properties با فیلتر وضعیت Sold |
| املاک اجاره‌داده‌شده | تعداد | /properties با فیلتر وضعیت Rented |

### اولویت نمایش KPIها
- در دسکتاپ می‌توان همه KPIها را در چند ردیف نمایش داد.
- در موبایل باید KPIهای مهم‌تر بالاتر باشند.
- KPIهای فروش و Dealها اولویت بالاتری دارند.
- KPIهای وظایف و املاک در اولویت بعدی قرار گیرند.

## 4. Chart Cards

### ساختار هر Chart Card
- عنوان فارسی
- فیلتر بازه زمانی در صورت نیاز
- نمودار
- Skeleton
- Empty State
- Error State با Retry
- در صورت نیاز، کلیک برای Drill-down

### نمودارهای اصلی

| نمودار | نوع | هدف |
|---|---|---|
| لیدها در بازه زمانی | Line یا Area | روند ایجاد لیدها |
| Dealها بر اساس Stage | Bar یا Column | توزیع Dealها در پایپ‌لاین |
| Funnel | Funnel | نرخ تبدیل مراحل فروش |
| درآمد/ارزش معاملات در بازه زمانی | Line یا Area | روند ارزش معاملات |
| عملکرد Agentها | Bar | مقایسه عملکرد Agentها |
| وضعیت املاک | Donut یا Bar | توزیع وضعیت املاک |
| منابع لید | Donut یا Bar | سهم منابع لید |

### قواعد نمودارها
- نمودارها باید فارسی و RTL باشند.
- Tooltipها باید فارسی باشند.
- محورهای نمودار باید خوانا باشند.
- رنگ نمودارها باید از Color System پیروی کند.
- نمودارها باید در Dark Mode خوانا باشند.
- نمودارها باید Skeleton داشته باشند.
- نمودارها باید Empty State داشته باشند.
- نمودارها باید با Date Range Selector هماهنگ باشند.
- نمودارها نباید داده حساس را بدون دسترسی نمایش دهند.

### Drill-down نمودارها
- کلیک روی نمودار لیدها باید به لیست مشتریان با فیلتر مرتبط برود.
- کلیک روی نمودار Dealها باید به لیست Dealها با فیلتر Stage برود.
- کلیک روی Funnel باید به گزارش Funnel برود.
- کلیک روی نمودار عملکرد Agentها باید به گزارش Agentها برود.
- کلیک روی نمودار وضعیت املاک باید به لیست املاک با فیلتر وضعیت برود.
- کلیک روی نمودار منابع لید باید به لیست مشتریان با فیلتر منبع برود.

## 5. Recent Activities

### هدف
نمایش آخرین فعالیت‌های ثبت‌شده برای کمک به پیگیری سریع.

### منابع فعالیت
- تعامل‌های اخیر
- تغییر Stage معاملات
- ایجاد مشتریان جدید
- ایجاد Dealهای جدید
- ثبت وظایف جدید در صورت نیاز

### ساختار هر آیتم
- آیکون نوع فعالیت
- عنوان کوتاه فارسی
- کاربر انجام‌دهنده
- زمان نسبی فارسی
- لینک به موجودیت مرتبط در صورت دسترسی

### نمونه آیتم‌ها
- «تماس تلفنی با مشتری ثبت شد»
- «معامله به مرحله مذاکره منتقل شد»
- «مشتری جدید ایجاد شد»
- «وظیفه جدید برای Agent ثبت شد»
- «ملک جدید ایجاد شد»

### قواعد
- Recent Activities باید حداکثر 5 تا 10 آیتم اولیه را نمایش دهد.
- باید لینک «مشاهده همه» به صفحه مرتبط داشته باشد.
- باید Skeleton داشته باشد.
- باید Empty State داشته باشد.
- باید در موبایل به‌صورت لیست ساده نمایش داده شود.
- نباید داده‌های غیرمجاز نمایش داده شود.

### هدف
نمایش سریع وظایف امروز و وظایف عقب‌افتاده.

### بخش‌ها
- وظایف امروز
- وظایف عقب‌افتاده
- دکمه «افزودن وظیفه سریع»
- لینک «مشاهده همه وظایف»

### ساختار هر Task Item
- عنوان وظیفه
- مسئول
- اولویت با Badge
- سررسید با تاریخ و ساعت فارسی
- وضعیت
- Checkbox یا دکمه تکمیل سریع

### قواعد

- وظایف امروز باید به ترتیب سررسید نمایش داده شوند.
- تکمیل سریع باید با API هماهنگ باشد.
- در صورت خطا، وضعیت وظیفه باید به حالت قبل برگردد.
- در صورت نداشتن وظیفه، Empty State کوتاه نمایش داده شود.
- در موبایل، Task Items باید ساده و قابل لمس باشند.

### هدف

### بخش‌ها
- تعداد نوتیفیکیشن‌های خوانده‌نشده

### ساختار هر Notification Item
- آیکون نوع نوتیفیکیشن

- متن کوتاه

- Notifications Widget نباید شلوغ شود.
- فقط 3 تا 5 نوتیفیکیشن اخیر نمایش داده شود.
- کلیک روی نوتیفیکیشن باید به صفحه مرتبط برود یا آن را خوانده کند.
- باید Skeleton داشته باشد.
- باید Empty State داشته باشد.
- باید در موبایل ساده و قابل لمس باشد.

## 8. Date Range Selector

### هدف
انتخاب بازه زمانی برای KPIها و نمودارها.

### گزینه‌های پیش‌فرض
- امروز
- 7 روز اخیر
- ماه جاری
- ماه گذشته
- 30 روز اخیر
- بازه دلخواه

### رفتار
- تغییر بازه باید KPIها و نمودارها را به‌روزرسانی کند.
- Skeleton باید هنگام تغییر بازه نمایش داده شود.
- بازه انتخابی باید در URL یا State ذخیره شود.
- در صورت فعال بودن مقایسه با دوره قبل، درصد تغییر محاسبه شود.
- بازه دلخواه باید با Date Picker شمسی انتخاب شود.
- در موبایل، Date Range Selector باید ساده و در دسترس باشد.

### قواعد
- بازه پیش‌فرض باید «ماه جاری» باشد.
- تاریخ‌ها باید شمسی نمایش داده شوند.
- مقایسه با دوره قبل باید اختیاری باشد.
- اگر داده‌ای برای بازه انتخابی نبود، Empty State نمایش داده شود.

## 9. فیلتر Agent و Pipeline

### فیلتر Agent
- برای Admin و Manager نمایش داده شود.
- برای Agent فقط مقدار خودش اعمال شود.
- باید با KPIها و نمودارها هماهنگ باشد.
- باید در URL یا State ذخیره شود.

### فیلتر Pipeline
- در نمودارهای مربوط به Dealها و Funnel اعمال شود.
- اگر فقط یک Pipeline فعال وجود دارد، می‌تواند به‌صورت پیش‌فرض پنهان باشد.
- باید با Date Range Selector هماهنگ باشد.

### قواعد
- فیلترها نباید Dashboard را بیش از حد پیچیده کنند.
- فیلترها باید قابل حذف باشند.
- فیلترهای غیرمجاز باید بر اساس نقش مخفی شوند.

## 10. Drill-down

### تعریف
Drill-down یعنی کاربر با کلیک روی KPI یا نمودار به لیست یا گزارش مرتبط برود و فیلترهای لازم از قبل اعمال شده باشند.

### قواعد
- Drill-down فقط در حد کلیک و رفتن به لیست مرتبط است.
- نباید Drill-down باعث ایجاد صفحات پیچیده جدید شود.
- فیلترها باید از طریق Query Params یا State منتقل شوند.
- صفحه مقصد باید Skeleton و Empty State داشته باشد.
- اگر کاربر دسترسی ندارد، Drill-down نباید انجام شود.

### نمونه‌ها
- KPI لیدهای جدید امروز → /clients با فیلتر تاریخ ایجاد امروز
- KPI Dealهای فعال → /deals با فیلتر وضعیت فعال
- نمودار Dealها بر اساس Stage → /deals با فیلتر Stage
- نمودار منابع لید → /clients با فیلتر منبع
- نمودار وضعیت املاک → /properties با فیلتر وضعیت
- KPI وظایف عقب‌افتاده → /tasks با فیلتر سررسید گذشته

## 11. حالت‌های داشبورد

### Loading
- Skeleton برای KPIها
- Skeleton برای نمودارها
- Skeleton برای Recent Activities
- Skeleton برای Tasks Widget
- Skeleton برای Notifications Widget

### Empty
- KPIها با مقدار صفر یا پیام کوتاه
- نمودارها با Empty State
- Recent Activities با پیام «فعالیتی ثبت نشده است»

- Notifications با پیام «نوتیفیکیشنی وجود ندارد»

### Error
- Error State برای دریافت KPIها
- Error State برای دریافت نمودارها
- Retry برای هر بخش
- پیام فارسی و قابل فهم
- عدم نمایش داده ناقص

### No Permission
- اگر کاربر به برخی بخش‌ها دسترسی ندارد، آن بخش‌ها نمایش داده نشوند.
- اگر کل Dashboard غیرمجاز است، صفحه No Permission نمایش داده شود.

## 12. نقش‌ها و دسترسی‌ها

| نقش | دسترسی داشبورد |
|---|---|
| Admin | همه KPIها، نمودارها و فیلترها |
| Manager | KPIها و نمودارهای تیم، فیلتر Agent |
| Agent | KPIها و نمودارهای مرتبط با خودش |
| Client | در این نسخه داشبورد کامل ندارد |

### قواعد
- Agent نباید داده Agentهای دیگر را ببیند.
- Manager می‌تواند داده تیم یا Agentهای تحت نظر را ببیند.
- Admin می‌تواند همه داده‌ها را ببیند.
- دسترسی‌ها باید در API نیز کنترل شوند، نه فقط UI.

## 13. رفتار داده‌ها

### دریافت داده
- Dashboard باید از APIهای جداگانه برای KPIها، نمودارها و ویجت‌ها استفاده کند.

- به‌روزرسانی دستی باید با دکمه Refresh در صورت نیاز ممکن باشد.

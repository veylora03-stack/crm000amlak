# دسترسی‌پذیری — CRM تخصصی املاک

این سند الزامات دسترسی‌پذیری محصول را تعریف می‌کند. هدف، رسیدن به حداقل استاندارد WCAG AA در حد امکانات یک CRM داخلی است. همه صفحات و کامپوننت‌ها باید با کیبورد، صفحه‌خوان و رنگ‌های قابل تشخیص قابل استفاده باشند.

---

## 1. اصول کلی

- محصول باید برای کاربران با کیبورد، موس و لمس قابل استفاده باشد.
- رنگ نباید تنها وسیله انتقال معنا باشد.
- همه عناصر تعاملی باید focus visible داشته باشند.
- همه فرم‌ها باید Label، توضیح و پیام خطای قابل فهم داشته باشند.
- همه پیام‌های خطا باید فارسی و قابل درک باشند.
- هیچ عملکردی نباید فقط با hover یا رنگ قابل تشخیص باشد.
- هدف‌های لمسی باید حداقل 44px در 44px باشند.
- ترتیب DOM باید منطقی و مطابق ترتیب بصری باشد.
- در RTL، جهت‌ها و آیکون‌ها باید معنای درست داشته باشند.

---

## 2. کنتراست رنگ

### استاندارد
- حداقل کنتراست متن اصلی نسبت به پس‌زمینه باید 4.5:1 باشد.
- متن بزرگ می‌تواند حداقل 3:1 باشد.
- آیکون‌ها و عناصر ضروری باید حداقل 3:1 کنتراست داشته باشند.
- Placeholder نباید به‌تنهایی اطلاعات مهم را منتقل کند.

### قواعد
- متن اصلی در Light Mode باید تیره و خوانا باشد.
- متن اصلی در Dark Mode نباید سفید خالص روی مشکی خالص باشد.
- متن روی دکمه Primary باید کنتراست کافی داشته باشد.
- پیام‌های success، warning، danger و info باید در هر دو حالت خوانا باشند.
- لینک‌ها باید از متن معمولی قابل تشخیص باشند.

---

## 3. Focus و Keyboard Navigation

### Focus Visible
- همه عناصر تعاملی باید focus ring واضح داشته باشند.
- focus ring نباید حذف شود.
- برای focus از رنگ primary یا outline قابل تشخیص استفاده شود.
- در Dark Mode focus باید همچنان قابل تشخیص باشد.

### Keyboard Navigation
- همه عناصر تعاملی باید با Tab قابل دسترسی باشند.
- ترتیب Tab باید منطقی باشد.
- Dropdownها باید با Arrow Keys پیمایش شوند.
- Modal و Drawer باید با Escape بسته شوند.
- در Modal باید focus trap فعال باشد.
- بعد از بستن Modal، focus باید به عنصری که Modal را باز کرده برگردد.
- Kanban باید با کیبورد قابل پیمایش باشد.
- جدول‌ها باید با کیبورد قابل پیمایش باشند.
- دکمه‌ها و لینک‌ها نباید فقط با موس قابل استفاده باشند.

### Skip Link
- در ابتدای صفحه باید Skip Link وجود داشته باشد.
- متن پیشنهادی: «پرش به محتوای اصلی»
- Skip Link باید با فوکوس کیبورد قابل مشاهده شود.
- باید کاربر را به main content ببرد.
- در موبایل نیز باید برای کیبورد و صفحه‌خوان در دسترس باشد.

---

## 4. ARIA و نقش‌ها

### قواعد عمومی
- از ARIA فقط وقتی استفاده شود که HTML معنایی کافی نیست.
- از roleها نباید بدون نیاز استفاده شود.
- aria-label باید برای آیکون‌های بدون متن تعریف شود.
- aria-describedby باید برای پیام خطا یا راهنمای فیلد استفاده شود.
- aria-expanded باید برای Dropdown، Accordion و Menu استفاده شود.
- aria-modal باید برای Modal استفاده شود.
- aria-live باید برای Toast و پیام‌های پویا با احتیاط استفاده شود.

### نمونه‌های لازم
- دکمه آیکونی: `aria-label`
- Notification Bell: `aria-label="نوتیفیکیشن‌ها"`
- دکمه Dark Mode: `aria-label="تغییر حالت روشن/تاریک"`
- دکمه بستن Modal: `aria-label="بستن"`
- جستجو: `aria-label="جستجوی سراسری"`
- Pagination: `aria-label="صفحه‌بندی"`
- جدول: `aria-label` یا عنوان مرتبط
- فرم: ارتباط Label با Input از طریق `for` و `id`

---

## 5. دسترسی‌پذیری فرم‌ها

### Label و شناسه
- هر Input باید Label قابل مشاهده داشته باشد.
- Label باید به Input متصل باشد.
- Placeholder نباید جایگزین Label شود.
- برای فیلدهای اجباری باید علامت یا متن «الزامی» وجود داشته باشد.

### پیام خطا
- پیام خطا باید به فیلد مرتبط باشد.
- باید از `aria-describedby` برای اتصال پیام خطا استفاده شود.
- پیام خطا باید با متن فارسی و واضح باشد.
- فوکوس باید به اولین فیلد دارای خطا برود.
- خطا نباید فقط با رنگ قرمز مشخص شود.

### دکمه‌ها و Submit
- دکمه Submit باید در حالت loading غیرفعال شود.
- از ارسال مجدد فرم جلوگیری شود.
- دکمه ذخیره باید با کیبورد قابل دسترس باشد.
- برای فرم‌های طولانی باید پیام Unsaved Changes قابل فهم باشد.

---

## 6. دسترسی‌پذیری جدول‌ها

- جدول‌ها باید از عناصر semantic مانند table، thead، tbody استفاده کنند.
- Header ستون‌ها باید قابل تشخیص باشد.
- در صورت امکان باید `caption` یا عنوان مرتبط داشته باشند.
- Sort باید با aria-sort یا متن قابل تشخیص باشد.
- Row کلیک‌پذیر باید با کیبورد قابل فعال‌سازی باشد.
- Row actions باید در Dropdown با دسترسی کیبورد قرار گیرند.
- در موبایل، کارت‌های جایگزین جدول باید قابل فوکوس باشند.
- Pagination باید label و وضعیت صفحه فعلی را مشخص کند.

---

## 7. دسترسی‌پذیری Kanban

- Board باید با کیبورد قابل پیمایش باشد.
- هر Stage باید عنوان و تعداد Dealها را مشخص کند.
- هر Deal Card باید با Enter یا Space باز شود.
- Drag & Drop نباید تنها روش جابجایی باشد.
- باید جایگزین کیبورد یا منوی «انتقال به Stage» وجود داشته باشد.
- در صورت جابجایی موفق یا ناموفق، باید بازخورد قابل فهم داده شود.
- Stage رنگی نباید تنها با رنگ مشخص شود؛ باید عنوان یا Badge نیز داشته باشد.
- Deal Card باید برای صفحه‌خوان اطلاعات اصلی را بدهد.

---

## 8. دسترسی‌پذیری Modal و Drawer

### Modal
- باید `role="dialog"` یا `aria-modal="true"` داشته باشد.
- focus اولیه باید داخل Modal باشد.
- focus trap باید فعال باشد.
- با Escape بسته شود.
- عنوان Modal باید توسط صفحه‌خوان خوانده شود.
- دکمه بستن باید aria-label داشته باشد.
- Overlay نباید با کلیک ناخواسته فرم دارای تغییر را ببندد.

### Drawer
- باید با Escape بسته شود.
- باید عنوان و نقش مشخص داشته باشد.
- focus باید مدیریت شود.
- در موبایل باید هدف‌های لمسی بزرگ باشند.
- بستن Drawer باید با دکمه واضح ممکن باشد.

---

## 9. دسترسی‌پذیری Toast و Alert

- Toast باید زمان کافی برای خواندن داشته باشد.
- Toast نباید تنها با رنگ معنا بدهد؛ باید آیکون و متن داشته باشد.
- برای Toastهای مهم می‌توان از `aria-live="polite"` استفاده کرد.
- Alertهای خطا باید قابل توجه باشند و با متن فارسی نمایش داده شوند.
- Toast نباید مانع فوکوس کیبورد شود.
- اگر Toast دارای دکمه اقدام است، باید با کیبورد قابل دسترس باشد.

---

## 10. دسترسی‌پذیری آیکون‌ها

- آیکون‌های تزئینی باید `aria-hidden="true"` داشته باشند.
- آیکون‌های عملیاتی باید `aria-label` داشته باشند.
- اگر آیکون همراه با متن است، می‌توان آیکون را مخفی از صفحه‌خوان کرد.
- آیکون‌های وضعیت باید با متن یا Tooltip همراه باشند.
- اندازه آیکون‌ها باید حداقل 16px باشد، اما هدف لمسی حداقل 44px باشد.

---

## 11. دسترسی‌پذیری نمودارها

- نمودارها باید عنوان قابل فهم داشته باشند.
- مقادیر مهم باید در جدول یا tooltip قابل دسترس باشند.
- رنگ‌های نمودار باید قابل تشخیص باشند.
- نباید فقط از رنگ برای تفکیک سری‌ها استفاده شود.
- در صورت امکان باید خلاصه متنی نمودار وجود داشته باشد.
- axis labels باید خوانا باشند.
- در Dark Mode باید کنتراست نمودارها حفظ شود.

---

## 12. دسترسی‌پذیری نقشه و گالری

### نقشه
- نقشه نباید تنها راه انتخاب موقعیت باشد.
- باید امکان ورود دستی Latitude/Longitude یا آدرس وجود داشته باشد.
- دکمه‌های نقشه باید با کیبورد قابل دسترس باشند.
- نقشه باید aria-label مناسب داشته باشد.

### گالری تصاویر
- تصاویر باید alt text داشته باشند.
- تصاویر تزئینی می‌توانند alt خالی داشته باشند.
- Thumbnailها باید با کیبورد قابل انتخاب باشند.
- Swipe در موبایل نباید تنها روش جابجایی باشد؛ باید دکمه قبلی/بعدی نیز وجود داشته باشد.
- دکمه‌های گالری باید aria-label داشته باشند.

---

## 13. هدف‌های لمسی و اندازه‌ها

- دکمه‌ها، آیکون‌های قابل کلیک، لینک‌ها و فیلدها باید حداقل هدف لمسی 44px داشته باشند.
- بین اهداف لمسی باید فاصله کافی وجود داشته باشد.
- در موبایل نباید دکمه‌ها خیلی نزدیک هم باشند.
- Checkbox، Radio و Switch باید هدف لمسی بزرگ‌تری از ظاهر خود داشته باشند.
- در جدول‌ها، آیکون‌های اقدام باید داخل یک دکمه با هدف لمسی مناسب باشند.

---

## 14. زبان و جهت

- زبان سند باید `fa` باشد.
- جهت سند باید `dir="rtl"` باشد.
- متن‌های فارسی باید با فونت خوانا نمایش داده شوند.
- اعداد و تاریخ‌ها باید فارسی نمایش داده شوند.
- برای فیلدهای لاتین مانند ایمیل یا موبایل می‌توان `dir="ltr"` استفاده کرد، اما Label فارسی بماند.
- پیام‌های سیستمی باید فارسی و محترمانه باشند.

---

## 15. Motion و کاهش حرکت

- انیمیشن‌ها باید کوتاه و ملایم باشند.
- اگر کاربر `prefers-reduced-motion` را فعال کرده باشد، انیمیشن‌های غیرضروری باید غیرفعال شوند.
- Drag & Drop باید Feedback واضح داشته باشد.
- Skeleton نباید چشمک‌زن شدید باشد.
- Modal و Drawer باید transition کوتاه داشته باشند.
- از حرکت‌های ناگهانی که باعث حواس‌پرتی شود پرهیز شود.

---

## 16. خطاها و بازخورد

- خطاها باید با متن، آیکون و رنگ مشخص شوند.
- خطای Validation باید به فیلد مرتبط باشد.
- خطای سرور باید با Alert قابل فهم باشد.
- پیام‌های موفقیت باید با Toast و آیکون success نمایش داده شوند.
- خطای No Permission باید واضح و محترمانه باشد.
- صفحه‌خوان باید از وضعیت‌های مهم مطلع شود، اما نباید پیام‌های زیاد و مزاحم بخواند.

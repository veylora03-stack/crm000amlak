# حالت‌های خطا، خالی و لودینگ — CRM تخصصی املاک

این سند متن‌ها، آیکون‌ها و اقدامات استاندارد برای حالت‌های Loading، Empty، Error، No Permission و Not Found را تعریف می‌کند. همه صفحات و کامپوننت‌ها باید از همین الگوها استفاده کنند.

---

## 1. اصول کلی

- هر حالت باید سه جزء داشته باشد: آیکون، عنوان فارسی، توضیح کوتاه فارسی.
- در صورت نیاز، باید CTA واضح داشته باشد.
- متن‌ها باید فارسی، کوتاه و محترمانه باشند.
- هیچ پیام فنی، Stack Trace یا خطای انگلیسی نباید به کاربر نمایش داده شود.
- حالت‌ها باید در Light Mode و Dark Mode خوانا باشند.
- حالت‌ها باید در موبایل و دسکتاپ درست نمایش داده شوند.
- Skeleton باید برای داده‌های اولیه استفاده شود.
- Spinner فقط برای اقدامات کوتاه داخل دکمه یا عملیات خاص استفاده شود.
- Error باید دکمه تلاش مجدد داشته باشد.
- Empty باید کاربر را به اقدام بعدی راهنمایی کند.

---

## 2. ساختار کامپوننت‌های حالت

### EmptyState
- آیکون
- عنوان
- توضیح
- CTA اختیاری

### ErrorState
- آیکون
- عنوان
- توضیح
- دکمه «تلاش مجدد»
- CTA ثانویه اختیاری

### LoadingSkeleton
- Skeleton متناسب با جدول، کارت، نمودار یا فرم
- بدون متن اضافی
- در صورت نیاز، متن کوتاه «در حال بارگذاری...» فقط برای عملیات دکمه

### NoPermissionState
- آیکون قفل
- عنوان «دسترسی ندارید»
- توضیح
- دکمه «بازگشت» یا «رفتن به داشبورد»

### NotFoundState
- آیکون جستجو یا فایل
- عنوان «یافت نشد»
- توضیح
- دکمه «بازگشت به لیست»

## 3. حالت Loading

### قواعد Skeleton
- Skeleton باید اندازه واقعی محتوا را شبیه‌سازی کند.
- Skeleton باید pulse ملایم داشته باشد.
- Skeleton نباید چشمک شدید داشته باشد.
- Skeleton باید در Dark Mode کم‌رنگ باشد.
- Skeleton باید برای جدول‌ها، کارت‌ها، نمودارها، Timeline و Kanban تعریف شود.

### متن‌های Loading
| محل | متن |

| تغییر Stage در Kanban | در حال به‌روزرسانی... |

### Skeletonهای استاندارد
| صفحه/کامپوننت | Skeleton |
|---|---|
| Dashboard | KPI Cards، نمودارها، فعالیت‌ها، وظایف |
| Clients | فیلترها، جدول، Pagination |
| Client Detail | اطلاعات اصلی، Timeline، Dealها |
| Properties | فیلترها، جدول، Pagination |
| Property Detail | گالری، اطلاعات، نقشه، Smart Match |

- آیکون: متناسب با ماژول
- عنوان: کوتاه و فارسی
- توضیح: یک جمله راهنما
- CTA: در صورت امکان، دکمه ایجاد یا حذف فیلترها

|---|---|---|---|---|

| Tasks با فیلتر | وظیفه‌ای با این فیلترها یافت نشد | فیلترها را تغییر دهید یا حذف کنید. | filter | حذف فیلترها |

### قواعد Empty
- Empty نباید با Error اشتباه گرفته شود.
- Empty باید رنگ خنثی داشته باشد.
- Empty باید در مرکز ناحیه مربوطه قرار گیرد.
- در موبایل، دکمه CTA باید قابل لمس باشد.
- اگر Empty به دلیل فیلتر است، باید CTA حذف فیلترها داشته باشد.
- اگر Empty به دلیل نبود داده اولیه است، باید CTA ایجاد داشته باشد.

## 5. حالت Error

### ساختار کلی
- آیکون: warning یا x-circle
- عنوان: کوتاه و فارسی
- توضیح: دلیل کلی بدون جزئیات فنی
- CTA: «تلاش مجدد»
- در صورت نیاز، CTA ثانویه: «بازگشت» یا «گزارش مشکل»

### خطاهای استاندارد

| نوع خطا | عنوان | توضیح | آیکون | CTA |
|---|---|---|---|---|
| Network Error | اتصال برقرار نشد | اتصال اینترنت را بررسی کنید و دوباره تلاش کنید. | wifi-off | تلاش مجدد |
| Server Error | خطای سرور | مشکلی در پردازش درخواست رخ داد. دوباره تلاش کنید. | server | تلاش مجدد |
| Timeout | درخواست طولانی شد | سرور به‌موقع پاسخ نداد. دوباره تلاش کنید. | clock | تلاش مجدد |
| Not Found | یافت نشد | رکورد مورد نظر وجود ندارد یا حذف شده است. | search | بازگشت به لیست |
| No Permission | دسترسی ندارید | برای مشاهده یا انجام این عملیات دسترسی کافی ندارید. | lock | بازگشت |
| Validation Error | اطلاعات واردشده کامل یا معتبر نیست | خطاهای مشخص‌شده را اصلاح کنید. | warning | بدون CTA |
| Export Error | خروجی تهیه نشد | تهیه فایل خروجی با مشکل مواجه شد. دوباره تلاش کنید. | file | تلاش مجدد |
| Import Error | فایل وارد نشد | فایل انتخاب‌شده معتبر نیست یا خطا دارد. | upload | انتخاب فایل جدید |
| Upload Error | فایل آپلود نشد | حجم فایل زیاد است یا فرمت آن مجاز نیست. | upload | انتخاب فایل جدید |
| Image Gallery Error | تصاویر بارگذاری نشدند | دریافت تصاویر با مشکل مواجه شد. | image | تلاش مجدد |
| Map Error | نقشه بارگذاری نشد | اتصال یا تنظیمات نقشه را بررسی کنید. | map-pin | تلاش مجدد |
| Dashboard Error | داشبورد بارگذاری نشد | دریافت اطلاعات داشبورد با مشکل مواجه شد. | chart | تلاش مجدد |
| KPI Error | دریافت شاخص ناموفق بود | بعضی از شاخص‌ها بارگذاری نشدند. | warning | تلاش مجدد |
| Chart Error | نمودار بارگذاری نشد | دریافت داده نمودار با مشکل مواجه شد. | chart | تلاش مجدد |
| Kanban Move Error | جابجایی معامله ناموفق بود | تغییر Stage ذخیره نشد. معامله به حالت قبل برگشت. | kanban | Undo یا تلاش مجدد |
| Auth Error | ورود انجام نشد | نام کاربری یا رمز عبور اشتباه است. | lock | بدون CTA |
| Token Expired | نشست شما منقضی شده است | لطفاً دوباره وارد شوید. | key | رفتن به ورود |
| Duplicate Error | رکورد تکراری است | این مقدار قبلاً ثبت شده است. | warning | بدون CTA |
| Delete Error | حذف انجام نشد | این رکورد به داده‌های دیگر وابسته است یا اجازه حذف ندارید. | trash | بدون CTA |

### قواعد Error
- Error باید همیشه دکمه «تلاش مجدد» داشته باشد، مگر در خطاهای Auth یا Validation.
- Error نباید داده ناقص یا قدیمی را به‌عنوان داده اصلی نشان دهد.
- خطای بخشی از صفحه نباید کل صفحه را از کار بیندازد.
- در Kanban، خطای جابجایی باید با Undo همراه باشد.
- در فرم‌ها، خطای Validation باید زیر فیلدها برود، نه به‌صورت Error State کلی.
- در خطای Token Expired، کاربر باید به Login هدایت شود.

## 6. حالت No Permission

### متن استاندارد
- عنوان: «دسترسی ندارید»
- توضیح: «برای مشاهده یا انجام این عملیات باید دسترسی مناسب داشته باشید.»
- آیکون: lock
- CTA:
  - «بازگشت»
  - «رفتن به داشبورد» در صورت نیاز

### قواعد
- No Permission باید قبل از Loading نمایش داده شود.
- نباید داده‌های غیرمجاز حتی به‌صورت Skeleton نمایش داده شوند.
- برای صفحات Admin-only، باید Router Guard و API Permission هر دو کنترل شوند.
- برای رکوردهای غیرمجاز، باید Not Found یا No Permission بسته به سیاست امنیتی نمایش داده شود.

---

## 7. حالت Not Found

### متن استاندارد
- عنوان: «یافت نشد»
- توضیح: «رکورد مورد نظر وجود ندارد یا ممکن است حذف شده باشد.»
- آیکون: search یا file
- CTA: «بازگشت به لیست»

### موارد استفاده
- Client Detail با id نامعتبر
- Property Detail با id نامعتبر
- Deal Drawer با id نامعتبر
- صفحه نامعتبر در Router
- گزارش یا فایلی که وجود ندارد

### قواعد
- Not Found نباید جزئیات فنی نشان دهد.
- اگر نبود رکورد به دلیل دسترسی است، بهتر است No Permission نمایش داده شود.
- در Router، صفحه 404 باید به داشبورد یا صفحه خطای عمومی لینک داشته باشد.

## 8. حالت Validation Error

### پیام‌های عمومی
- «این فیلد الزامی است.»
- «مقدار واردشده معتبر نیست.»
- «فرمت واردشده صحیح نیست.»
- «این مقدار تکراری است.»
- «مقدار باید بزرگ‌تر از صفر باشد.»
- «مقدار نمی‌تواند منفی باشد.»
- «طول مقدار واردشده بیش از حد مجاز است.»
- «فایل انتخاب‌شده مجاز نیست.»
- «حجم فایل بیشتر از 10 مگابایت است.»

### پیام‌های اختصاصی
| فیلد | پیام |
|---|---|
| موبایل | شماره موبایل معتبر نیست. |
| ایمیل | ایمیل معتبر نیست. |
| قیمت | مبلغ باید عدد صحیح و مثبت باشد. |
| متراژ | متراژ باید عدد مثبت باشد. |
| تاریخ سررسید | تاریخ سررسید نمی‌تواند در گذشته باشد. |
| بودجه حداقل/حداکثر | بودجه حداقل نمی‌تواند بیشتر از بودجه حداکثر باشد. |
| رمز عبور | رمز عبور باید حداقل 8 کاراکتر و شامل حرف و عدد باشد. |
| تکرار رمز عبور | تکرار رمز عبور با رمز جدید یکسان نیست. |
| فایل | فرمت فایل مجاز نیست. |
| تصویر | فرمت تصویر باید jpg، jpeg، png یا webp باشد. |
| عنوان | عنوان الزامی است. |
| مشتری | انتخاب مشتری الزامی است. |
| Stage | انتخاب Stage الزامی است. |

### قواعد
- Validation Error باید زیر فیلد مرتبط نمایش داده شود.
- Border فیلد باید danger شود.
- فوکوس باید به اولین فیلد خطا برود.
- اگر خطا از سرور آمد، باید به فیلد مرتبط نگاشت شود.
- اگر خطا به فیلد خاصی مرتبط نبود، Alert سراسری نمایش داده شود.

## 13. دسترسی‌پذیری حالت‌ها

- Empty و Error باید با متن قابل فهم باشند، نه فقط آیکون.
- دکمه CTA باید با کیبورد قابل دسترس باشد.
- Toast موفقیت یا خطا باید با aria-live مناسب اعلام شود.
- Skeleton نباید برای صفحه‌خوان پرش زیاد ایجاد کند.
- در Error، فوکوس نباید گم شود.
- در Modal یا Drawer، حالت خطا باید داخل همان Modal/Drawer نمایش داده شود.
- دکمه تلاش مجدد باید focus visible داشته باشد.

---

## 14. رفتار در موبایل

- Empty و Error باید تک‌ستونه شوند.
- دکمه CTA باید حداقل هدف لمسی 44px داشته باشد.
- متن‌ها نباید خیلی طولانی شوند.
- آیکون باید در بالای متن قرار گیرد.
- در جدول‌هایی که به کارت تبدیل می‌شوند، Empty و Error باید به‌صورت کارت مرکزی نمایش داده شوند.

---

## 15. رفتار در Dark Mode

- آیکون‌ها باید از رنگ‌های semantic استفاده کنند.
- عنوان باید text-primary باشد.
- توضیح باید text-secondary باشد.
- CTA باید در Dark Mode کنتراست کافی داشته باشد.
- Skeleton باید کم‌رنگ‌تر از Light Mode باشد.
- Error نباید در Dark Mode بیش از حد درخشان باشد.

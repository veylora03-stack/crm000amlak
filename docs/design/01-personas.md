# پرسوناها — CRM تخصصی املاک

## 1. Admin — مدیر سیستم

### معرفی
مدیر سیستم مسئول پیکربندی کلی، مدیریت کاربران، تنظیمات، دسترسی‌ها و نظارت بر سلامت سیستم است.

### اهداف اصلی
- ایجاد و مدیریت کاربران
- تعیین نقش‌ها و دسترسی‌ها
- پیکربندی Pipelineها، Stageها و تنظیمات سیستم
- مشاهده Audit Log برای بررسی تغییرات
- اطمینان از امنیت و عملکرد صحیح سیستم

### نیازهای کلیدی
- دسترسی سریع به مدیریت کاربران
- دید کامل به تنظیمات سیستم
- امکان فعال/غیرفعال کردن کاربران
- دسترسی به گزارش‌ها و لاگ‌ها

### نقاط درد
- شلوغی صفحات مدیریتی
- دسترسی‌های نامشخص کاربران
- نبود گزارش از تغییرات انجام‌شده

### رفتارهای مورد انتظار
- استفاده بیشتر از دسکتاپ
- مراجعه مکرر به Settings و Users
- نیاز به تأیید قبل از عملیات حساس

### دسترسی‌ها
- دسترسی کامل به همه بخش‌ها
- مدیریت کاربران و نقش‌ها
- مشاهده Audit Log
- تنظیمات سیستم

---

## 2. Manager — مدیر فروش / سرپرست تیم

### معرفی
مدیر فروش مسئول نظارت بر عملکرد Agentها، مدیریت Pipeline، تخصیص لیدها و بررسی گزارش‌ها است.

### اهداف اصلی
- بررسی عملکرد Agentها
- نظارت بر Dealها و وضعیت Pipeline
- تخصیص مشتری‌ها به Agentها
- دریافت گزارش‌های دوره‌ای
- بررسی Funnel و نرخ تبدیل

### نیازهای کلیدی
- داشبورد تحلیلی
- فیلتر بر اساس Agent و Pipeline
- گزارش‌های قابل خروجی Excel/CSV
- دید سریع به وظایف و فعالیت تیم

### نقاط درد
- پراکندگی اطلاعات تیم
- نبود دید سریع از وضعیت Dealها
- دشواری در مقایسه عملکرد Agentها

### رفتارهای مورد انتظار
- استفاده بیشتر از دسکتاپ و گاهی موبایل
- تمرکز روی Dashboard و Reports
- بررسی دوره‌ای Pipeline و Tasks

### دسترسی‌ها
- مشاهده Dealها، مشتری‌ها و فعالیت‌های تیم
- تخصیص مشتری‌ها
- مشاهده گزارش‌ها
- مدیریت Pipelineها در حد مجاز

---

## 3. Agent — کارشناس فروش / مشاور املاک

### معرفی
Agent کاربر اصلی روزمره سیستم است و با مشتری‌ها، ملک‌ها، Dealها، تعامل‌ها و وظایف سروکار دارد.

### اهداف اصلی
- ثبت مشتری جدید
- ثبت ملک جدید
- پیگیری مشتری‌ها
- ثبت تماس‌ها و تعامل‌ها
- ایجاد و جابجایی Dealها در Kanban
- انجام وظایف روزانه

### نیازهای کلیدی
- سرعت بالا در ثبت اطلاعات
- فرم‌های ساده و در دسترس
- Timeline مشتری و Deal
- جستجوی سریع
- یادآورها و وظایف امروز

### نقاط درد
- ورود اطلاعات تکراری
- فرم‌های طولانی
- فراموشی پیگیری‌ها
- شلوغی بیش از حد رابط کاربری

### رفتارهای مورد انتظار
- استفاده زیاد از سیستم در طول روز
- استفاده از دسکتاپ و موبایل
- جابجایی سریع بین مشتری‌ها، ملک‌ها و Dealها
- استفاده مکرر از جستجو و Kanban

### دسترسی‌ها
- مشاهده و مدیریت مشتری‌ها، Dealها و وظایف مرتبط با خودش یا تیم تعریف‌شده
- ثبت تعامل‌ها
- ایجاد و ویرایش ملک‌ها بر اساس دسترسی
- مشاهده Dashboard شخصی

---

## 4. Client — مشتری نهایی

### معرفی
مشتری نهایی تنها به اطلاعات مرتبط با خودش دسترسی دارد و نباید داده‌های سایر کاربران را مشاهده کند.

### اهداف اصلی
- مشاهده وضعیت درخواست‌ها یا Dealهای مرتبط
- مشاهده اطلاعات مرتبط با خودش
- دریافت پیام‌ها یا نوتیفیکیشن‌های داخلی محدود در صورت نیاز

### نیازهای کلیدی
- رابط بسیار ساده
- جلوگیری از نمایش داده‌های غیرمرتبط
- پیام‌های واضح و قابل فهم

### نقاط درد
- دیدن اطلاعات غیرمرتبط
- پیچیدگی صفحات مدیریتی
- عدم وضوح وضعیت فرآیند

### رفتارهای مورد انتظار
- استفاده محدودتر نسبت به Agent و Manager
- مشاهده صفحات ساده و مشخص
- عدم تعامل با بخش‌های مدیریتی

### دسترسی‌ها
- فقط داده‌های مرتبط با خودش
- عدم دسترسی به تنظیمات، کاربران، گزارش‌ها و Audit Log
- دسترسی محدود بر اساس نقش Client

---

## جمع‌بندی طراحی بر اساس پرسوناها

| پرسونا | تمرکز اصلی | صفحات کلیدی |
|---|---|---|
| Admin | پیکربندی، کاربران، امنیت | Settings, Users, Audit Log |
| Manager | نظارت، گزارش، عملکرد تیم | Dashboard, Reports, Pipeline |
| Agent | کار روزانه، ثبت و پیگیری | Clients, Properties, Pipeline, Tasks |
| Client | مشاهده داده محدود | صفحات محدود مرتبط با مشتری |

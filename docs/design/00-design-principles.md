# اصول طراحی UI/UX — CRM تخصصی املاک

## 1. سادگی
- رابط کاربری باید کمینه‌گرا، روشن و بدون عناصر اضافی باشد.
- هر صفحه فقط باید یک هدف اصلی را به‌خوبی پشتیبانی کند.
- از شلوغی بصری، رنگ‌های اضافی و المان‌های غیرضروری پرهیز شود.
- اقدامات اصلی باید در دسترس و واضح باشند.

## 2. سرعت
- بارگذاری صفحات باید سریع باشد.
- استفاده از Skeleton Loading برای جلوگیری از احساس کندی.
- جستجو باید با Debounce انجام شود.
- جدول‌ها و لیست‌ها باید با Pagination سمت سرور کار کنند.
- از درخواست‌های غیرضروری API پرهیز شود.

## 3. وضوح
- متن‌ها باید فارسی، کوتاه، واضح و قابل فهم باشند.
- وضعیت‌های موفقیت، خطا، هشدار و اطلاعاتی باید با رنگ و آیکون مشخص شوند.
- عنوان صفحات، فرم‌ها و جدول‌ها باید مشخص و قابل تشخیص باشند.
- هیچ پیام مبهم یا فنی بدون نیاز نباید به کاربر نمایش داده شود.

## 4. RTL کامل
- کل محصول باید راست‌به‌چپ باشد.
- Sidebar باید در سمت راست قرار گیرد.
- آیکون‌ها، فاصله‌ها، Alignment و رفتار کامپوننت‌ها باید با RTL سازگار باشند.
- اعداد و تاریخ‌ها باید در نمایش نهایی فارسی و متناسب با زبان فارسی باشند.

## 5. دسترسی‌پذیری
- کنتراست رنگ‌ها باید حداقل در سطح AA باشد.
- Focus باید همیشه قابل مشاهده باشد.
- Navigation با کیبورد باید ممکن باشد.
- دکمه‌ها و فیلدها باید دارای aria-label مناسب باشند.
- حداقل اندازه هدف لمسی برای دکمه‌ها و آیکون‌های قابل کلیک 44px باشد.
- Skip Link برای عبور از منوها و رسیدن به محتوای اصلی در نظر گرفته شود.

## 6. موبایل‌فرست
- طراحی باید ابتدا برای موبایل انجام شود و سپس برای دسکتاپ گسترش یابد.
- جدول‌ها در موبایل باید به کارت، لیست ساده یا Scroll افقی تبدیل شوند.
- Sidebar در موبایل باید به‌صورت کشویی باشد.
- فرم‌ها در موبایل باید تک‌ستونه شوند.
- Kanban در موبایل باید Scroll افقی داشته باشد.

## 7. Dark Mode
- محصول باید دارای حالت روشن و تاریک باشد.
- رنگ‌های Dark Mode باید جداگانه تعریف شوند.
- از رنگ سیاه خالص برای پس‌زمینه استفاده نشود.
- انتخاب کاربر باید در localStorage ذخیره شود.
- حالت سیستمی نیز باید پشتیبانی شود.

## 8. حالت‌های خطا و خالی
- هیچ صفحه‌ای نباید بدون حالت Loading، Empty و Error باشد.
- Empty State باید شامل متن فارسی، آیکون و در صورت نیاز دکمه اقدام باشد.
- Error State باید شامل پیام واضح، آیکون و امکان تلاش مجدد باشد.
- Validation Errors باید به‌صورت فارسی و در کنار فیلد مرتبط نمایش داده شوند.

## 9. کاهش کلیک‌های اضافی
- اقدامات پرکاربرد باید در دسترس باشند.
- از Modal یا Drawer برای ویرایش‌های سریع استفاده شود.
- از تأیید غیرضروری برای عملیات کم‌خطر پرهیز شود.
- فرم‌ها باید با کمترین ورودی ممکن تکمیل شوند.
- امکان جستجوی سریع در Topbar فراهم شود.

## 10. ثبات و یکپارچگی
- کامپوننت‌ها باید در تمام صفحات رفتار یکسانی داشته باشند.
- فاصله‌ها، رنگ‌ها، سایه‌ها و گوشه‌ها باید از Design Tokens پیروی کنند.
- الگوهای رفتاری مانند ذخیره، حذف، فیلتر و Pagination باید یکسان باشند.
- تغییرات ناگهانی و رفتارهای غیرقابل پیش‌بینی ممنوع است.

## 11. بازخورد
- هر اقدام کاربر باید بازخورد مشخص داشته باشد.
- موفقیت عملیات باید با Toast نمایش داده شود.
- عملیات طولانی باید با Loading یا Skeleton نمایش داده شود.
- Drag & Drop در Kanban باید بازخورد بصری فوری داشته باشد.
- از Optimistic Update در حد مجاز استفاده شود.

## 12. امنیت و اعتماد
- عملیات‌های حساس مانند حذف باید با تأیید مناسب همراه باشند.
- هیچ داده واقعی بدون تأیید کاربر حذف نشود.
- دسترسی‌های مبتنی بر نقش باید در UI نیز مشخص باشند.
- صفحات بدون دسترسی باید حالت No Permission داشته باشند.

# جداول و فیلترها — CRM تخصصی املاک

این سند رفتار استاندارد جدول‌ها، فیلترها، مرتب‌سازی و صفحه‌بندی را تعریف می‌کند. همه جدول‌های اصلی باید از همین الگو پیروی کنند.

---

## 1. اصول کلی جداول

- همه جدول‌ها باید server-side pagination داشته باشند.
- همه جدول‌ها باید sort، فیلتر و جستجو را پشتیبانی کنند.
- کلیک روی Row باید به صفحه Detail برود.
- Row Hover باید واضح باشد.
- Header جدول باید sticky باشد.
- جدول‌ها باید در موبایل به کارت یا scroll افقی تبدیل شوند.
- Bulk Actions باید برای عملیات‌های مجاز فراهم باشد.
- Column Visibility باید برای ستون‌های قابل انتخاب فعال باشد.
- Density اختیاری است و می‌تواند compact، normal و comfortable باشد.
- Loading، Empty و Error State باید برای همه جدول‌ها تعریف شود.

---

## 2. ساختار استاندارد جدول

### بخش‌های اصلی
- PageHeader با عنوان و دکمه اقدام اصلی
- نوار فیلترها و جستجو
- جدول اصلی
- Pagination در پایین جدول
- Bulk Actions در صورت انتخاب Row

### الگوی چیدمان
- دسکتاپ: جدول کامل با Header sticky
- تبلت: جدول با scroll افقی در صورت نیاز
- موبایل: کارت‌های ساده یا scroll افقی

### فاصله‌ها
- فاصله PageHeader تا فیلترها: 24px
- فاصله فیلترها تا جدول: 16px
- فاصله جدول تا Pagination: 16px

---

## 3. Server-Side Pagination

### الزامات
- همه listها باید با API Pagination شوند.
- page_size پیش‌فرض: 20
- max_page_size: 100
- کاربر نباید بتواند همه داده‌ها را یکجا دریافت کند.
- Pagination باید شامل page، page_size و total باشد.

### کامپوننت Pagination
- نمایش شماره صفحه فعلی
- نمایش تعداد کل نتایج
- انتخاب تعداد آیتم در هر صفحه
- دکمه‌های قبلی/بعدی
- در موبایل، ساده و فشرده باشد

### رفتار
- تغییر صفحه باید Skeleton یا Loading نشان دهد.
- فیلترها باید هنگام تغییر page حفظ شوند.
- Sort باید هنگام تغییر page حفظ شود.
- جستجو باید هنگام تغییر page حفظ شود.
- بعد از حذف یک آیتم، باید صفحه مناسب نمایش داده شود.

## 4. Sort و مرتب‌سازی

### رفتار
- کلیک روی Header باید sort را فعال کند.
- کلیک اول: صعودی
- کلیک دوم: نزولی
- کلیک سوم: حذف sort
- آیکون sort باید واضح باشد.
- sort باید به سرور ارسال شود.
- فقط ستون‌های قابل sort باید sort داشته باشند.

### پیاده‌سازی
- sort باید با پارامتر ordering به API ارسال شود.
- برای sort نزولی از `-` قبل از فیلد استفاده شود.
- sort باید با فیلترها و جستجو همزمان کار کند.
- sort باید در URL یا State ذخیره شود.

### ستون‌های قابل sort
- نام/عنوان
- تاریخ ایجاد
- تاریخ به‌روزرسانی
- قیمت
- وضعیت
- مسئول
- اولویت
- سررسید

## 5. فیلترها

### رفتار
- فیلترها باید بالای جدول قرار گیرند.
- فیلترها باید به سرور ارسال شوند.
- فیلترها باید با Debounce برای جستجو کار کنند.
- فیلترها باید در URL یا State ذخیره شوند.
- فیلترهای فعال باید با Badge نشان داده شوند.
- دکمه حذف فیلترها باید در دسترس باشد.

### انواع فیلتر
- فیلتر متنی با جستجو
- فیلتر انتخابی با Select
- فیلتر چندانتخابی با MultiSelect
- فیلتر تاریخ با Date Picker
- فیلتر محدوده با دو فیلد حداقل/حداکثر
- فیلتر وضعیت با Badge یا Select

### قواعد
- فیلترها باید فارسی باشند.
- فیلترها باید با هم ترکیب شوند.
- حذف یک فیلتر نباید بقیه را پاک کند.
- فیلترهای زیاد باید جمع‌شونده باشند.
- در موبایل، فیلترها باید در Drawer یا Modal باز شوند.

### فیلترهای استاندارد هر ماژول

#### مشتریان
- وضعیت لید
- نوع مشتری
- منبع لید
- مسئول پیگیری
- محدوده بودجه
- تاریخ ایجاد

#### املاک
- نوع ملک
- وضعیت انتشار
- وضعیت معامله
- نوع آگهی
- محدوده قیمت
- شهر/منطقه
- مسئول

#### Dealها
- Pipeline
- Stage
- Agent مسئول
- وضعیت برد/باخت
- محدوده مبلغ
- تاریخ تخمینی

#### وظایف
- مسئول
- اولویت
- وضعیت
- محدوده سررسید
- مرتبط با مشتری/Deal/ملک

## 6. جستجو

### رفتار
- جستجو باید در نوار فیلترها قرار گیرد.
- جستجو باید Debounce حداقل 300ms داشته باشد.
- جستجو باید به سرور ارسال شود.
- جستجو باید Skeleton نشان دهد.
- Empty State برای نتیجه نداشتن لازم است.
- جستجو باید با فیلترها همزمان کار کند.

### فیلدهای جستجو
- مشتریان: نام، موبایل، ایمیل
- املاک: کد، عنوان، آدرس، شهر
- Dealها: عنوان، مشتری، ملک
- وظایف: عنوان، توضیحات
- کاربران: نام، نام کاربری، ایمیل

## 7. Bulk Select و Bulk Actions

### رفتار
- Checkbox در ابتدای هر Row برای انتخاب
- Checkbox در Header برای انتخاب همه در صفحه
- انتخاب همه فقط در صفحه فعلی اعمال شود.
- Bulk Actions باید در نوار بالای جدول ظاهر شوند.
- Bulk Actions باید تأیید بگیرند.
- Bulk Actions باید با API کار کنند.

### Bulk Actions مجاز
- حذف نرم
- تغییر وضعیت
- تخصیص مسئول
- Export انتخاب‌شده‌ها

### قواعد
- Bulk Actions نباید بدون تأیید انجام شوند.
- Bulk Actions باید Loading نشان دهند.
- Bulk Actions باید Toast موفقیت یا خطا نشان دهند.
- بعد از Bulk Action، انتخاب‌ها باید پاک شوند.
- در موبایل، Bulk Actions باید ساده باشند.

## 9. Density

### رفتار
- Density باید اختیاری باشد.
- Density باید در localStorage ذخیره شود.
- Density باید سه حالت داشته باشد:
  - compact: برای داده زیاد
  - normal: حالت پیش‌فرض
  - comfortable: برای خوانایی بیشتر

### مقادیر
| Density | Row Height | Padding |
|---|---:|---:|
| compact | 32px | 8px |
| normal | 40px | 12px |
| comfortable | 48px | 16px |

### قواعد
- Density نباید خوانایی را کاهش دهد.
- Density باید در موبایل به‌صورت خودکار comfortable باشد.
- Density نباید باعث تغییر عرض ستون‌ها شود.

## 19. حالت‌های جدول

### Loading
- Skeleton برای ردیف‌ها
- Skeleton برای Header
- Skeleton برای Pagination

### Empty
- Empty State با آیکون و متن فارسی
- دکمه CTA در صورت نیاز
- دکمه حذف فیلترها در صورت فعال بودن فیلترها

### Error
- Error State با دکمه Retry
- پیام فارسی
- عدم نمایش داده‌های ناقص

### No Permission
- پیام دسترسی ندارید
- دکمه بازگشت

### No Results
- Empty State مخصوص جستجو یا فیلتر
- دکمه پاک کردن جستجو یا فیلترها

## 20. جدول در موبایل

### رفتار
- جدول باید به کارت تبدیل شود یا scroll افقی داشته باشد.
- برای لیست مشتریان و املاک، کارت پیشنهاد می‌شود.
- برای لیست Dealها، کارت یا scroll افقی مناسب است.
- برای لیست وظایف، کارت مناسب است.
- برای لیست کاربران، کارت مناسب است.

### ساختار کارت
- عنوان اصلی
- وضعیت با Badge
- اطلاعات کلیدی
- اقدامات محدود

### قواعد
- کارت‌ها باید قابل کلیک باشند.
- کارت‌ها باید هدف لمسی کافی داشته باشند.
- Bulk Actions در موبایل باید ساده شوند.
- Pagination در موبایل باید ساده شود.

## 22. دسترسی‌پذیری جداول

- Row کلیک‌پذیر باید با کیبورد قابل فعال‌سازی باشد.
- Checkboxها باید با کیبورد قابل دسترس باشند.

- Row Actions باید با کیبورد قابل دسترس باشند.
